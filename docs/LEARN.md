# Режим обучения

Блоки VAG не сообщают, как называются их каналы адаптации и где они лежат. ODIS и VCDS берут это из
своих закрытых баз. VagOn узнаёт это **на вашей машине**: делает снимок всех идентификаторов
блока, вы меняете **одну** настройку любым способом, VagOn делает второй снимок и находит, какой DID
и какие биты изменились.

Изменение можно сделать:
* в меню MMI (например, «Свет → Coming home: 30 с»);
* в **ODIS через VNCI** (Windows) — удобно для «активаций», которых нет в меню;
* в OBDeleven / VCDS / Car Scanner.

## Пример 1 — научить рецепт каналу (по одному каналу)

Рецепт `mmi.developer_mode` ссылается на канал «Developer mode» в блоке 5F. Чтобы он заработал:

```bash
vagon learn start 5F
#  → в первый раз VagOn опросит блок (только чтение, на ELM327 ~10–15 мин; прогресс сохраняется)
#  → включите «Developer mode» в ODIS/OBDeleven
vagon learn finish 5F --name "Developer mode" --old "not activated" --new "activated" --session 0x4F
vagon recipe check mmi.developer_mode      # теперь рецепт знает DID вашего блока
```

`--name` — имя канала **как в рецепте** (`vagon recipe show <id>` покажет имена). Если в рецепте
несколько каналов (беспроводной CarPlay — 4–6 каналов), учите их по одному: `start` → поменять один
канал → `finish --name …` → следующий.

## Пример 2 — записать целое изменение как свой рецепт

Если не хочется разбирать по каналам: сделайте в ODIS всю процедуру (например, все «7 строк» для
беспроводного CarPlay) между `start` и `finish`:

```bash
vagon learn start 5F
#  … сделать все изменения в ODIS …
vagon learn finish 5F --recipe-name "Беспроводной CarPlay (ODIS)" --login 20103
vagon recipe off user.besprovodnoy_carplay_odis    # откат к заводскому
vagon recipe on  user.besprovodnoy_carplay_odis    # снова включить
```

Рецепт меняет **только изменившиеся биты** (не весь DID), поэтому не затирает другие настройки,
лежащие рядом. Он привязан к ODX‑датасету вашего блока: после обновления ПО блока VagOn откажется его
применять, пока вы не переучите.

## Пример 3 — числовые значения

Если указать старое и новое значение числами, VagOn вычислит масштаб:

```bash
vagon learn start 09
#  MMI: Coming home 10 с → 30 с
vagon learn finish 09 --name "Coming home duration" --old 10 --new 30
vagon labels list 09        # Coming home duration = 30 (DID 0x…, шаг 10 с)
```
Числовой канал занимает целые байты. Если VagOn угадал поле неверно, задайте его явно:
`--bit 0 --bits 16`.

## Пример 4 — что изменил ODIS в кодировании всех блоков

Без обучения и опросов: полная копия до и после сеанса в ODIS/OBDeleven.
```bash
vagon backup-all          # до
#  … сеанс в ODIS (кодирование любых блоков) …
vagon backup-all          # после
vagon diff                # по каждому блоку: какие байты/биты кодирования поменялись
```
Найденные биты можно оформить своим рецептом (`coding_bit`, см. [RECIPES.md](RECIPES.md)).

## Советы

* Меняйте **одну** вещь за раз — иначе в диффе окажется несколько DID (VagOn предупредит).
* Значения, которые меняются сами (счётчики, напряжения), VagOn отбрасывает: он делает два снимка
  «до» и исключает всё, что изменилось между ними. Данные мастерской F198/F199 тоже игнорируются.
* Первичный опрос по умолчанию — диапазоны `0000‑0FFF` и `2000‑3FFF`. Если изменение не нашлось,
  опросите шире: `vagon did 5F sweep --ranges full` (долго, но один раз), затем снова `learn start 5F`.
* Выученные метки: `~/.vagon/labels/user.json`, рецепты: `~/.vagon/recipes/learned.json`.
  Их можно скопировать на iPhone (папка `VagOn` в Pythonista) — DID у одной и той же машины те же.
* В веб‑интерфейсе — вкладка «Обучение» (то же самое кнопками).
