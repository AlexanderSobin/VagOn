# Технические детали

## Шина и адресация

На MQB/MQB‑Evo диагностика идёт по UDS (ISO 14229) поверх ISO‑TP (ISO 15765‑2) на CAN 500 кбит/с,
11‑битные идентификаторы, через шлюз (19). У каждого блока пара CAN ID; для блоков VAG
**ответ = запрос + 0x6A**, у двигателя/КПП — схема OBD‑II (0x7E0 → 0x7E8). Таблица в
`vagon/vag/modules.py` (источник — логические связи ODIS, github.com/ConnorHowell/vag-uds-ids):

| Блок | Запрос | Ответ |
|---|---|---|
| 01 Двигатель | 7E0 | 7E8 |
| 09 Центральная электроника | 70E | 778 |
| 17 Приборная панель | 714 | 77E |
| 19 Шлюз | 710 | 77A |
| 44 Усилитель руля | 712 | 77C |
| 5F Мультимедиа | 773 | 7DD |
| A5 Фронтальная камера | 74F | 7B9 |

## Идентификаторы (DID)

| DID | Что |
|---|---|
| F187 | номер детали VW |
| F189 | версия ПО |
| F191 / F1A3 | номер / версия железа |
| F197 | имя системы |
| F19E / F1A2 | ODX‑датасет (ASAM) / его версия — по нему подбираются метки и рецепты |
| F190 | VIN |
| F1A5 | «отпечаток» кодирования (код мастерской последнего кодирования) |
| F198 | код мастерской / тестера — пишется перед кодированием |
| F199 | дата программирования, BCD `YY MM DD` — пишется перед кодированием |
| 0600 | **длинное кодирование** |

## Последовательность записи (как у ODIS/VCDS)

```
10 03                         расширенная сессия (или 10 4F — сессия разработчика)
27 03  → 67 03 <seed 4 байта>   Security Access, уровень 3
27 04 <seed + логин-код>        ключ = (seed + код) mod 2^32
2E F1 99 <YY MM DD BCD>
2E F1 98 <F1A5>
2E <DID> <данные>
22 <DID>                       обратное чтение и сравнение
```
Логин по коду — это задокументированная процедура мастерской (её же используют openpilot
`vw_mqb_config.py` для блока 44 с кодом 28183 и clusterleg для 17 с кодом 20103). Это не обход SFD.

## ELM327: ловушки и как VagOn их обходит

1. **Flow control на неверный ID.** Режим FC по умолчанию шлёт кадр управления потоком на
   «ID ответа − 8». Для 0x778 это 0x770 — другой блок, и длинный ответ обрывается после первого кадра.
   VagOn ставит `ATFCSH <ID запроса>`, `ATFCSD 30 00 <STmin>`, `ATFCSM1` для каждого блока, а на
   клонах без этих команд выключает авто‑FC (`ATCFC0`) и сам отправляет кадр `30 00 <STmin>` на ID
   запроса в ответ на First Frame (успевая в таймаут N_Bs блока).
2. **Отправка > 7 байт.** С `ATCAF1` ELM327 отправляет только одиночные кадры. VagOn сам режет запрос:
   `ATCAF0`, First Frame (`ATR1`, ждёт FC от блока), consecutive frames с `ATR0` (не ждать ответа),
   последний кадр с `ATR1`.
3. **Ожидание после FC.** После полученного кадра ELM327 ещё `ATST × 4 мс` слушает шину и лишь потом
   печатает `>`. С `ATSTFF` это ~1 с — больше таймаута N_Cr блока (1 с), и блок сбрасывает приём.
   VagOn ставит `ATST32` (200 мс) на время First Frame и возвращает `ATSTFF` перед последним кадром.
4. **Переполнение буфера.** STmin 10 мс в FC, чтобы адаптер успевал печатать кадры (`--stmin`).
5. **Пустая строка повторяет последнюю команду** — VagOn никогда её не отправляет.
6. **Эхо** включено и проверяется: «недослышанная» команда обнаруживается.
7. **STN (OBDLink, vLinker)** — используется `STPX` для длинных запросов.
8. **Ответ «ожидайте» (0x78).** Плохие клоны перестают слушать через `ATST`. Тогда VagOn проверяет
   результат записи обратным чтением.

Все эти случаи воспроизводит эмулятор (`vagon/sim/elm.py`) — в т.ч. неверный FC режима 0 и
таймаут N_Cr на виртуальных часах, — и тесты проверяют, что драйвер их обходит
(`tests/test_elm.py`).

## Обучение (learn)

`sweep` читает DID в диапазонах (только чтение) и запоминает существующие. `learn start` делает два
снимка (исключая «живые» значения), `finish` — третий, дифф → минимальное битовое поле
(`vagon/vag/learn.py`). Метки хранятся по ODX‑датасету блока, поэтому подходят только к той же
версии данных.

## Тесты

```bash
python3 -m pip install pytest
python3 -m pytest
```
Сквозные тесты гоняют настоящий драйвер ELM327 по байтам через эмулятор (AT‑команды, эхо, CAN‑кадры,
ISO‑TP, UDS, SFD, логин, F198/F199), а также веб‑API, CLI и BLE‑обёртку Pythonista (на подставном
модуле `cb`). Минимальная версия Python — 3.10 (как в Pythonista).
