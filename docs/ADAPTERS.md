# Адаптеры

## ELM327 (в т.ч. Rokodil)

VagOn говорит с машиной через любой ELM327‑совместимый адаптер: Wi‑Fi, Bluetooth LE,
Bluetooth classic, USB. Что важно знать про ваш Rokodil:

1. **Какой у него канал?** Посмотрите на коробке/в инструкции:
   * «Wi‑Fi» → работает и на Mac, и на iPhone (`-a wifi`);
   * «Bluetooth 4.0 / BLE / для iOS» → Mac (`-a ble`, нужен `bleak`) и iPhone (Pythonista);
   * «Bluetooth» без 4.0 / только Android → классический Bluetooth: только Mac (`serial:///dev/cu.…`);
   * Rokodil ScanX/ScanX Pro с экраном — это автономный сканер, а не адаптер ELM327; VagOn с ним
     работать не будет.
2. **Насколько он «полный»?** Для VAG нужно, чтобы адаптер выполнял:
   `ATSH`, `ATCRA`, `ATFCSH`, `ATFCSD`, `ATFCSM1`, `ATCAF0/1`, `ATR0/1`, `ATST`.
   Команда `vagon info` проверит это при подключении. Если адаптер не понимает `ATFCSM1`, VagOn
   выключит его собственный flow control и будет отвечать блоку сам — работает, но длинные ответы
   читаются медленнее. Хорошие варианты: OBDLink (STN), vLinker MC/FS, Veepeak BLE+,
   «ELM327 v1.5 на PIC18F25K80».

### Что VagOn делает с ELM327 иначе, чем «обычные» OBD‑программы

* Включает заголовки и сам собирает многокадровые ответы ISO‑TP (надёжнее, чем доверять клону).
* Настраивает flow control на **ID запроса** блока (`ATFCSH 70E` для блока 09). По умолчанию ELM327
  отправил бы его на «ответ − 8» (для 09 это 0x770 — совсем другой блок), и длинные ответы VAG‑блоков
  не приходили бы. Если адаптер этих команд не знает — `ATCFC0` и собственный кадр Flow Control.
* Сам отправляет длинные запросы (запись кодирования длиннее 7 байт) кадр за кадром: ELM327 с
  автоформатированием умеет отправлять только одиночные кадры. При этом время ожидания после
  Flow Control сокращается до 200 мс — иначе блок не дождётся следующего кадра (таймаут N_Cr 1 с).
  На чипах STN используется `STPX`.
* Пауза между кадрами от блока (STmin, по умолчанию 10 мс), чтобы дешёвый адаптер не переполнялся
  (`BUFFER FULL`). Меняется `--stmin`.

## VNCI 6154A (и другие VAS‑клоны)

VNCI работает через драйверы VAS6154 / D‑PDU API **только под Windows** (для ODIS). Драйверов для
macOS и iOS нет, а протокол закрыт — поэтому VagOn не может использовать VNCI напрямую на Mac/iPhone.
На Mac с Apple Silicon Windows‑драйверы VNCI в виртуальной машине (ARM‑Windows) тоже, как правило,
не работают; на Intel‑Mac — работают в Boot Camp/Parallels.

Как VNCI полезен вместе с VagOn:

* **Обучение из ODIS.** Подключите VagOn (ELM327) — `vagon learn start 5F`, отключите ELM327,
  сделайте нужное изменение в ODIS через VNCI, снова подключите ELM327 — `vagon learn finish 5F
  --recipe-name "…"`. VagOn запомнит точные DID и биты и дальше сможет включать/выключать это с
  Mac/iPhone (см. [LEARN.md](LEARN.md)).
* Для работ, которые VagOn сознательно не делает (прошивка, SVM, базовые установки с GFF), — ODIS.

## Симулятор

`-a sim` — встроенный эмулятор ELM327 + Audi A3 8Y: настоящий обмен AT‑командами и CAN‑кадрами,
блоки с логин‑кодами, сессиями, требованиями F198/F199, защитой SFD (`-a "sim://?sfd=5F,17"`).
Состояние сохраняется между запусками (`vagon sim-reset` — сброс). Для отдельного «Wi‑Fi адаптера»
на порту: `vagon sim --port 35000`, затем `vagon -a tcp://127.0.0.1:35000 …`.
